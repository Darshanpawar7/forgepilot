A coding agent that asks before it writes.

ForgePilot is a VS Code extension whose agent loop runs on TrueForge. The editor becomes a set of MCP tools, and TrueForge's own tool approval opens every proposed edit in VS Code's diff editor, hunk by hunk, before a single byte reaches disk.

How it works

TrueForge's approval is the review button.

ForgePilot doesn't bolt a confirm dialog onto a chatbot. It lists the write tools in TrueForge's requireApprovalForTools, so the agent loop itself stops and waits for the diff review.

1

The agent calls a tool

Gemini, running inside TrueForge, calls edit_file on the extension's MCP server.

2

TrueForge pauses

The turn stops with tool.approval_required. The stream stays open.

3

You review hunks

ForgePilot builds the whole proposed file and opens VS Code's diff editor with a tick list of hunks.

4

Allow or deny

user.tool_approval goes back to TrueForge, with a reason the agent can act on if you deny.

5

Only then, the write

The MCP tool writes exactly the accepted hunks through a WorkspaceEdit, and the change can be undone.

Resilience

When a model fails, your files don't.

Rate limits and overloads get a real back-off, then the agent continues in the same TrueForge session, so it keeps everything it already read and did. Hard errors fall back to the next model in your list. Because nothing is written without approval, a failure can't leave a half-applied edit.

Under the hood

Small surface, deep integration.

TrueForge local modeRuns the agent loop, sessions and turns, and tool approval; it also switches models across the providers configured in it. The extension never calls a model provider itself.
MCP server in the extensionStreamable HTTP on 127.0.0.1 with a random bearer token: list_files, search_code, get_symbols, read_file, edit_file, create_file, run_command.
Diff reviewVS Code's diff editor plus a hunk checklist (jsdiff). Partial accepts write only the ticked hunks.
Back-off, resume, fallback429s wait 20 / 40 / 60 s, overloads 5 / 10 / 20 s, then a new turn continues the same session. Hard errors fall back through forgepilot.models. No keys in the repository.
Cancellationsessions.cancel, running commands killed, pending reviews dropped. Edits are atomic, so nothing is half-applied.
UndoEvery applied change goes on an undo stack; one command reverts it.
Honest notes. The demo's review clicks are scripted so it fits in four minutes; the same review UI is used by hand. In the recorded Task B, one of the agent's edits didn't match the file text and was rejected automatically; it re-read the file and retried. The free tier rate-limited it six times, which is why the video speeds those waits up. The write-up lists all limitations and the tools used, including the AI assistance used while building.
